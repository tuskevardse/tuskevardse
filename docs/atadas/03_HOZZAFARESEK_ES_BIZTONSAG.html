Hozzáférések és biztonság

Ez a dokumentum azt rögzíti, milyen rendszerekhez kell hozzáférést adni, mit nem szabad átadni sima üzenetben, és milyen biztonsági szabályokat kell megtartani.

1. Hozzáférések, amelyeket accounton belül kell adni

  • GitHub: repository collaborator vagy organization/team hozzáférés.
  • Cloudflare: account member hozzáférés megfelelő jogosultsággal.
  • ZTS / ZeroTime Services: domain admin vagy DNS/delegáció kezelési hozzáférés.
  • Google Workspace / Google Calendar: admin vagy naptárszerkesztői hozzáférés.
  • Codex / fejlesztői környezet: lokális repo és parancsfuttatási lehetőség.

2. Amit nem szabad emailben vagy chatben elküldeni

  • GitHub token
  • Cloudflare API token
  • Google service account JSON kulcs
  • jelszó
  • bankkártyaadat
  • privát gyermekadat
  • nem publikus naptár vagy dokumentum érzékeny tartalma

3. GitHub biztonsági szabályok

  • Publikus repositoryba titok nem kerülhet.
  • A .secrets/ mappa nem commitolható.
  • Commit előtt mindig legyen git status.
  • Ha véletlenül titok került commitba, azonnal kulcscsere szükséges, nem elég a fájlt törölni.

4. Cloudflare biztonsági szabályok

  • Production deploy csak ismert GitHub branchből történjen.
  • Environment variable csak akkor legyen, ha tényleg szükséges.
  • KV/D1/R2/Workers binding ne legyen kötelező elem, ha a 0 Ft-os modell a cél.
  • Domain és DNS módosítás előtt fel kell írni a régi rekordokat.

5. ZTS és DNS biztonság

  • A domain delegáció kritikus hozzáférés.
  • Cloudflare nameservereket csak a Cloudflare adott domainhez mutatott értékei alapján szabad megadni.
  • Email rekordokat DNS only módban kell tartani.
  • MX/SPF/DKIM/DMARC módosítást csak kontrollált átállásként szabad végezni.

6. Google és naptár biztonság

  • Publikus Google Calendarba csak nyilvános program kerüljön.
  • Belső sportági alkalmak külön naptárba kerüljenek jogosultsággal.
  • Google API/service account csak akkor használható, ha a költség- és billingkockázat vállalt.
  • Ha nincs kártyaadat megadása, előnyben kell részesíteni a kézi Calendar kezelést és embedet.

7. Gyerekadat-kezelési alapelvek

A publikus honlapra kerülő információt úgy kell kezelni, mintha bárki, bármikor, később is visszakereshetné.
  • Ne kerüljön publikus oldalra gyermek teljes neve.
  • Ne kerüljön publikus oldalra egészségügyi, rehabilitációs vagy fejlesztési részlet.
  • Szűk korosztályos vagy érzékeny programnál általános megfogalmazás javasolt.
  • Konkrét személyes ügyet mindig közvetlen egyeztetésre kell irányítani.

8. AI és preprompt biztonság

  • A publikus AI prompt nem tartalmazhat belső titkot.
  • Az AI válasz nem tekinthető hivatalos döntésnek.
  • API/billing nélküli modellben csak másolható preprompt vagy külső AI link használható.
  • Beágyazott AI chathez backend, API kulcs és költségkontroll kellene.
