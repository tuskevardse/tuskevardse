Fejlesztés és deploy

Ez a dokumentum a fejlesztői környezet felállítását, a lokális ellenőrzést, a GitHub munkafolyamatot és a Cloudflare produkcióba vitelt foglalja össze.

1. Lokális környezet

Az átvevő gépén szükséges:

  • Node.js
  • npm
  • Git
  • GitHub hozzáférés a repositoryhoz
  • Codex vagy más fejlesztői editor

2. Projekt indítása

cd C:\Projects\Tuskevar-DSE
npm ci
npm run dev

Lokális teszt URL:

http://127.0.0.1:3000/
http://localhost:3000/

3. Kötelező ellenőrzések

Minden commit/push előtt fusson le:

npm run lint
npm run build

A sikeres build statikus kimenetet készít az out/ mappába.

4. GitHub workflow

git status
git diff
git add .
git commit -m "Rövid, érthető commit üzenet"
git push

A repository alapága a main. Kisebb tartalmi változás közvetlenül mehet main-re, nagyobb szerkezeti vagy konfigurációs módosításhoz külön branch javasolt.

5. GitHub jogosultság

Az átvevőnek legalább write jogosultság kell a repositoryhoz. Ellenőrzés:

  • GitHub repository → Settings → Collaborators and teams
  • meghívó elfogadva,
  • write vagy admin jogosultság,
  • credential manager beállítva.
git config --global credential.helper manager

6. Cloudflare deploy

A normál deploy automatikus:

git push
  -> GitHub frissül
  -> Cloudflare build/deploy indul
  -> production oldal frissül

Worker/static asset deploy esetén használt beállítás:

Build command:
npm run build

Deploy command:
npx wrangler deploy --assets=./out --name=tuskevardse --compatibility-date=2026-06-16

Tiszta Cloudflare Pages static hosting esetén:

Build command:
npm run build

Build output directory:
out

7. Deploy utáni ellenőrzés

  • Cloudflare Deployments státusz sikeres-e.
  • Preview/production URL betölt-e.
  • Menü, mobil nézet, eseménynaptár, AI prompt oldal működik-e.
  • Kapcsolati email linkek működnek-e.

8. Hibás deploy kezelése

  • Először Cloudflare build logot kell nézni.
  • Lokálisan reprodukálni: npm run build.
  • Ha tartalmi hiba: javítás, commit, push.
  • Ha vissza kell vonni: git revert <commit-sha>, majd push.
Nem javasolt kézzel feltölteni build kimenetet GitHub megkerülésével. A tartós forrás mindig a Git repository.
